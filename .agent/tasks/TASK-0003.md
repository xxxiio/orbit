# Task: M27 GitHub distribution, first-run experience and user documentation

## Objective

Deliver the M27 installation, initialization, diagnostics, update and end-user documentation work so a new user can install a verified release without Rust or Python and operate Orbit through real workflows.

## Current behaviour

Orbit builds and passes the Linux M15 acceptance profile. Installation requires the source tree or a locally built archive. There is no root GitHub installer, no versioned user configuration, no `orbit init`, `orbit doctor` or `orbit update`, and no coherent end-user documentation entry point covering installation, initialization and everyday workflows.

## Desired behaviour

A user can run the documented curl installer or install an explicit release, use `orbit init` to create `~/.orbit/config.toml` and a local SQLite workspace, run `orbit doctor` for read-only diagnostics, and use `orbit update --check`/`orbit update` for a verified GitHub-managed update. Documentation uses only implemented commands and covers installation, first project, everyday work, agent workflows, connected mode, MCP, backup/recovery and troubleshooting.

## Scope

- M27 Workstreams A-F: release workflow, root installer, unified configuration and init, doctor/update, end-user documentation, release/install acceptance.
- One shared configuration resolver used by CLI, TUI and MCP.
- Reuse of the M26 transactional archive installer and existing packaging utilities.
- Source-backed and compiled-CLI documentation checks.

## Out of scope

- Publishing an official stable GitHub Release without maintainer authorization.
- Completing deferred M25 capability actions, connected MCP outbox parity, blueprint upgrade or habit extraction.
- Windows, cross-compilation, package-manager integrations, hosted docs, signing keys or TLS certification.
- Automatic database downgrades or background service installation.

## Dependencies

- MILESTONE-0015 Linux executable acceptance baseline.
- MILESTONE-0023 optional agent execution.
- MILESTONE-0026 packaging and archive installer.
- M25 I1/I2 blueprint surfaces already documented as supported.

## Risks

- Installer or update rollback defects could overwrite unrelated binaries; every path uses the managed manifest and staged replacement with preservation tests.
- Configuration precedence could diverge across adapters; one resolver with pure tests is required.
- Update could irreversibly migrate a database; a read-only backup must succeed before replacement.
- Documentation could drift; tests must execute the compiled CLI help and validate links and config examples.
- Fixture release tests do not prove a public GitHub Release exists; readiness must be reported separately.

## Acceptance criteria

- [ ] AC-001: Release workflow builds canonical checksummed archives for the declared Linux/macOS matrix, validates version consistency, records metadata, attests provenance, and publishes only gated draft releases unless explicitly authorized.
- [x] AC-002: Root `install.sh` detects supported platforms, resolves stable or explicit versions, verifies checksums and reuses the transactional installer without Rust or Python.
- [x] AC-003: `orbit init` creates the documented layout, config and SQLite workspace idempotently while preserving existing configuration and data.
- [x] AC-004: Configuration precedence is CLI > environment > config file > defaults, `ORBIT_DB` remains an override, and incomplete connected settings fail closed across CLI/TUI/MCP.
- [x] AC-005: `orbit doctor` performs read-only diagnostics with actionable remediation and no secret disclosure.
- [x] AC-006: `orbit update`/`--check` verifies artifacts, respects channels, refuses unmanaged installs, backs up the database and preserves the prior binary/data on failure.
- [x] AC-007: End-user documentation covers installation, initialization, first project, everyday workflows, agent work, connected mode, MCP, backup/recovery and troubleshooting with implemented commands.
- [x] AC-008: Automated release, installer, init/doctor/update and documentation checks pass; the M15 acceptance suite remains green.
- [x] AC-009: GetDone and roadmap status reflect evidence and separate fixture acceptance from a real published release.
