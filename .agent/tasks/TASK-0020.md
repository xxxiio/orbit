# Task: I5 — MCP/Herdr coverage, failure injection, real recovery rehearsal, documentation and acceptance

## Objective

The backup/restore system is proven against the records MCP/Herdr agent work
produces, exercised through a real recovery rehearsal and a failure-injection
matrix, documented for operators, and honestly accepted against EC-012–EC-015.

## Specification

- Coverage: agent-job records, reviews/receipts/handoffs, workflow definitions,
  installed capability metadata, MCP-made task/milestone changes and activity/
  event records survive restoration.
- External-boundary exclusions are documented: external Herdr sessions, running
  processes, git worktrees/branches, external repositories, external credentials
  and unaccepted disconnected-client actions.
- Recovery never automatically re-executes external agent or capability actions;
  uncertain external execution is marked for reconciliation.
- Failure injection: interrupted backup, corrupted archive, missing attachment,
  unreadable vault file, disk-full/permission failure, unsupported manifest
  version, wrong destination, restore while target active, interrupted
  restoration, missing external agent session, pending connected-client outbox.
  The original workspace remains recoverable in every case.
- Real recovery rehearsal: deterministic realistic dataset. Sequence: create →
  verify → disposable changes → isolated restore → isolated instance opens →
  earlier data/relationships/activity present → later changes absent → agent
  records readable → no automatic external execution → disposable write → restart
  persistence, with recorded before/after counts and content hashes.
- Documentation: backup-and-recovery guide, upgrades-and-recovery, local web
  quickstart, self-hosting, CLI reference, Web GUI guide, architecture and
  records; must state same-disk backups are not disk-failure protection and must
  not claim zero data loss or zero downtime.

## Ordered plan

1. Audit which authoritative records and external boundaries exist and write the
   coverage/exclusion matrix.
2. Add MCP/Herdr record and no-re-execution coverage tests.
3. Build the deterministic rehearsal dataset and run the full rehearsal sequence

4. Build the failure-injection matrix and prove the original workspace remains
   recoverable in each case.
5. Update the documentation set and the documentation tests.
6. Record EC-012–EC-015 evidence and close the milestone acceptance honestly.
