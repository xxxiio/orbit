# Task: I2 — Restore engine: preflight, isolated restore, maintenance replacement and rollback

## Objective

A person can preview, perform and recover a restore safely: preflight reports
exactly what will happen, an isolated restore opens as a working Orbit instance,
and replacing an existing workspace happens only behind explicit authorization, a
maintenance boundary and a preserved rollback copy.

## Specification

- `orbit backup restore --dry-run` reports target workspace, backup source, schema
  compatibility, objects replaced, preservation plan, required downtime, connected-
  client warnings and non-restorable external dependencies, and mutates nothing.
- Isolated restore extracts and verifies an archive into a new location, then opens
  it as a working Orbit instance; the active workspace is never overwritten.
- Replacing an existing workspace requires explicit authorization/confirmation and
  a maintenance boundary; a live active-server database is never overwritten in
  place.
- Replacement stages and verifies the restored workspace before switching, keeps
  the previous workspace for rollback, and fails closed when connected-replica
  state cannot be safely reconciled.
- Connected-mode limitations are reported: client outbox commands and staged
  uploads are not in a server backup; reconciliation is required after recovery.
- Client replica snapshots are refused as a recovery point in this build.
- CLI: `orbit backup restore` with the same service the Web GUI reuses.
- Failure cases: target active, wrong destination, interrupted restoration,
  incompatible schema, missing external dependency and incompatible connected
  replica state.

## Ordered plan

1. Implement archive extraction with path-safety and hash verification into a
   staging location.
2. Implement the preflight/dry-run report and prove it mutates nothing.
3. Implement isolated restore to a new location and open the restored instance.
4. Implement the maintenance replacement path with explicit authorization, a
   maintenance boundary, staged verification, switch and rollback preservation.
5. Add connected-replica detection and fail-closed reconciliation behaviour.
6. Wire `orbit backup restore` to the service.
7. Add integration and failure tests; record evidence for EC-005..EC-007.
