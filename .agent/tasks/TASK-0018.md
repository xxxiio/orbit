# Task: I3 — Web backup management: server API and Backup & Restore settings UI

## Objective

The Web GUI exposes a Backup & Restore settings section that lists, creates,
downloads/exports, inspects, verifies and schedules workspace backups and drives
isolated restore and controlled recovery, through server endpoints that reuse the
shared Rust backup service and the existing authorization architecture.

## Specification

- Server endpoints call the same backup/restore service as the CLI; they do not
  duplicate archive logic or accept arbitrary browser-supplied server paths.
- The settings section shows overview, last backup, destination, schedule, history
  and verification status/errors.
- Actions: create, download/export, inspect, verify, schedule configuration,
  restore preflight, isolated restore and controlled recovery for replacement.
- Destructive restore is clearly separated from ordinary actions and confirmed;
  replacement never happens from the browser (offline maintenance plan only).
- Authorization follows the existing server architecture; the local-trusted
  principal keeps only its product-level privileges.
- Archive download/export is memory-buffered and capped; product responses are
  path-free.
- Failure cases: no destination configured, backup in progress, verification
  failure, concurrent restore, expired session/CSRF failure and unauthorized
  administrative restore.

## Ordered plan

1. Define the server request/response contracts for list, create, inspect, verify,
   download/export, schedule and restore preflight/recovery.
2. Implement the handlers on top of the shared service with the existing
   authorization and CSRF rules.
3. Build the Backup & Restore settings section with overview, history, verification
   status and schedule controls.
4. Add isolated restore and the separated, confirmed controlled-recovery flow.
5. Add web unit tests and a Playwright spec against a real isolated server.
6. Record evidence for EC-009; update the Web GUI guide when accepted.
